# 井温监控模块设计

## 目标

在侧栏“措施分析”之后新增“井温监控”模块。用户上传井筒温度压力测试表后，系统保存测试数据，并按测试记录展示温度、压力随井深变化的曲线及射孔井段。

## 数据导入与覆盖规则

- 接收 `.xlsx` 文件，读取第一个工作表，从第 3 行起读取有效测点。
- 井号与测试日期优先取文件首条有效数据的 C、D 列；文件名中的 `井号（YYYY-MM-DD）` 作为缺失时的回退来源。
- 测点字段：E 列测试深度、F 列射孔井段顶深、G 列射孔井段底深、H 列温度、I 列压力。
- 仅保存测试深度为数值且温度或压力至少一个为数值的行；按测试深度升序保存。
- 用 `井号 + 测试日期` 作为唯一业务键。重复上传该组合时，在事务内删除旧测点并写入新文件数据；同一井号的不同测试日期保留为独立历史记录。

## 数据模型与接口

新增独立 SQLite 表，不与措施记录耦合：

- `well_temperature_tests`：`id`、`well_no`、`test_date`、`perforation_top_depth`、`perforation_bottom_depth`、`point_count`、`source_file`、`created_at`、`updated_at`，并对 `(well_no, test_date)` 建唯一索引。
- `well_temperature_points`：`id`、`test_id`、`depth`、`temperature`、`pressure`。

新增接口：

- `POST /api/well-temperature-tests/import`：上传并替换同井同日记录，返回测试摘要与测点数。
- `GET /api/well-temperature-tests`：返回全部测试记录，支持井号筛选，按井号和日期倒序。
- `GET /api/well-temperature-tests/:id`：返回选中测试的摘要和测点。
- `DELETE /api/well-temperature-tests/:id`：删除一条测试及其测点。

## 界面

- 在“措施分析”后新增“井温监控”侧栏项与页面标题。
- 页面顶部提供 Excel 上传按钮与导入反馈。
- 左侧为井号筛选和历史测试记录列表；选择一条记录后显示其井号、日期和测点数。
- 右侧并排展示两张 ECharts 曲线：温度—井深与压力—井深。纵轴为井深且 `inverse: true`，使深度从上到下增加。
- 两张图均以浅黄色 `markArea` 显示射孔顶深到射孔底深的区间，并标注两个深度值；文件无有效射孔数据时不显示该区间。

## 错误处理与验证

- 拒绝非 `.xlsx` 文件、无有效测点、无法确定井号或测试日期的文件，并返回明确错误信息。
- 后端导入解析的自动化测试使用提供的样例文件，验证井号 `高2-2-96`、日期 `2026-06-21`、E/H/I 映射、射孔段 `1555.6–1610.1` 和重复上传覆盖规则。
- 前端构建验证页面编译；接口级验证上传、列表、详情和覆盖结果。
