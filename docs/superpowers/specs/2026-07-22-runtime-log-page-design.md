# 运行日志入口设计

## 目标

移除应用顶部栏中的同步、缓存与错误文本，避免技术日志占用全局页面空间；在侧边栏提供独立的“运行日志”页面集中查看这些状态。

## 界面与交互

- 顶部栏仅保留当前页面标题、搜索与用户信息，不再渲染同步状态、缓存提示或错误详情。
- “基本情况”菜单组新增“运行日志”入口。
- 运行日志页面展示数据更新日期、同步状态、缓存预热状态和缓存来源。
- 同步失败时，完整错误消息只在运行日志页的错误区域显示；正常状态时显示清晰的成功/进行中状态。
- 首页保留业务数据更新时间卡片，但不展示技术错误详情。

## 技术边界

- 复用现有 `syncStatus`、`cacheInfo`、`cacheSourceText` 和同步状态，不新增接口或数据持久化。
- 修改侧边栏配置和 `App.tsx` 的导航、标题与日志页渲染。
- 不改动现有同步、缓存、首页指标及数据加载逻辑。

## 验证

- 导航测试覆盖“运行日志”入口及其菜单组。
- 源码测试覆盖顶部栏不再渲染同步状态详情，并覆盖日志页渲染错误信息。
- 执行 `npm test`、`npm run lint`、`npm run build`；若 lint 仍存在既有无关错误，单独记录。
