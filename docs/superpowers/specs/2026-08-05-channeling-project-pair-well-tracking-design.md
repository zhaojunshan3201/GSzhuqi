# 注窜项目、井对与单井三级跟踪设计

**日期：** 2026-08-05
**状态：** 已完成交互设计确认，待用户审阅书面规格

## 1. 背景与目标

现有“注窜项目台账”能够保存项目级治理信息，并维护“注入井 → 采油井”的静态注窜关系，但缺少以下能力：

- 项目治理过程只保存当前字段，不能按时间追溯历次处理。
- 井对没有独立详情、联动曲线和效果评价。
- 单井不能脱离项目独立建档和持续跟踪。
- 项目指标不能由关联井的生产和注汽数据自动汇总。

本次设计建立“项目—井对—单井”三级联动跟踪体系：保留项目级治理台账，为每条关系提供井对详情，同时增加可独立存在的单井档案。系统自动读取已有生产与注汽数据，管理员补充治理过程和人工结论，游客保持只读。

## 2. 范围

### 2.1 本次包含

- 项目详情中的自动汇总指标和项目治理时间线。
- 每条注窜关系后的“查看详情/跟踪记录”入口。
- 井对详情中的关系信息、联动曲线、效果评价和时间线。
- 独立单井跟踪台账及单井详情。
- 注入井、采油井和双角色井的自适应指标。
- 项目、井对、单井共用的可关联跟踪事件。
- 治理评价的指标快照、人工结论和历史保护。
- 管理员维护与游客只读权限。

### 2.2 本次不包含

- 在注窜模块内修改 `production` 或 `injection_stage_rows` 原始数据。
- 使用模型自动判定注窜成立或自动生成治理结论。
- 新增真实文件上传与附件存储；本期事件仅保存文字证据和附件说明。
- 替代现有生产日报、注汽计划或注汽阶段导入流程。

## 3. 信息架构

采用三级联动详情页，不把所有功能继续堆叠在现有项目台账页面。

### 3.1 项目详情

现有项目详情保留，并分为三个页签：

1. **概览：** 项目基本信息、风险、自动汇总指标和人工项目评价。
2. **井对关系：** 当前项目的关系清单，每行提供“查看详情/跟踪记录”。
3. **跟踪时间线：** 项目状态变化、治理措施、执行、评价、复查、关闭和复发记录。

### 3.2 井对详情

井对详情以一条 `channeling_relations` 记录为对象，包含：

1. **关系信息：** 类型、注入井、采油井、层系、证据、影响等级、置信度、来源、责任人、有效期和状态。
2. **联动曲线：** 上层显示注入井注汽阶段和注汽量，下层显示采油井日产油、日产液和含水曲线，使用同一日期轴。
3. **治理评价：** 选择执行日期及前后对比区间，计算前后均值、变化量和变化率，并填写人工结论。
4. **跟踪时间线：** 只显示关联到该井对的事件。

注入井和采油井井号均可进入对应单井档案。

### 3.3 单井跟踪台账与详情

新增独立的“单井跟踪台账”入口。没有加入项目、没有井对关系的井也可以先建档，之后通过规范化井号自动关联项目和井对。

单井详情分为：

1. **概览：** 井号、区块、负责人、自动识别的井角色和最新指标。
2. **生产/注汽曲线：** 根据井角色显示相应数据。
3. **关联关系：** 该井参与的全部项目和井对，可反向跳转。
4. **跟踪时间线：** 单井发现、措施、执行、评价、复查和复发历史。

同一规范化井号只能拥有一个单井档案，不因参加多个项目而复制。

## 4. 数据来源与指标

### 4.1 井号关联

系统生成 `normalized_well_no` 用于匹配：去除首尾空格并统一大小写。界面仍显示原始井号。生产数据、注汽数据、关系记录和单井档案均通过规范化井号关联。

匹配失败时显示“未找到生产/注汽数据”和最后查询时间，不把缺失数据当作 0。

### 4.2 注入井指标

从现有 `injection_stage_rows` 读取：

- 周期开始日期与结束日期；
- 单周期注汽量；
- 选定日期范围内累计注汽量；
- 注汽周期次数；
- 温度、压力、干度和生产时长；
- 注汽周期时间轴。

上述字段缺失时显示“未提供”，不推算、不展示虚假值。

### 4.3 采油井指标

从现有 `production` 读取：

- 最新日产油、日产液和含水；
- 近 7 日和近 30 日均值；
- 指定范围内日产油、日产液和含水趋势；
- 治理前后均值、变化量和变化率。

同一口井兼具注入井与采油井角色时，同时显示两组模块。角色由现有关系和数据自动判断，不要求用户手工选择。

### 4.4 项目自动汇总

项目只汇总其关联关系中的井，并按规范化井号去重：

- 关系总数、有效关系数和已解除关系数；
- 注入井数、采油井数和涉及单井总数；
- 选定日期范围内累计注汽量；
- 关联采油井合计日产油及其变化；
- 已完成效果评价的数量和最近评价结论。

项目概览默认使用最新可用数据日期向前 30 天；用户可以调整统计日期范围。项目人工评价与自动汇总并列展示，人工输入不覆盖原始数据或自动计算结果。

### 4.5 井对效果对比

效果评价默认以治理执行日期为分界，比较前后各 30 天；用户可修改开始、分界和结束日期。统计时忽略缺失日，不补 0，并显示实际有效天数。

每次提交评价时保存：

- 数据查询时间和数据来源；
- 前后对比日期范围；
- 有效数据天数；
- 自动计算指标；
- 缺失字段列表；
- 人工结论、证据说明和负责人。

历史评价使用保存时的指标快照。点击“按最新数据重新计算”会创建新评价，不改写旧评价。

## 5. 跟踪时间线

### 5.1 事件类型

统一支持以下事件：

- 发现问题；
- 制定措施；
- 执行记录；
- 效果评价；
- 复查；
- 关闭；
- 复发；
- 状态变更；
- 关系确认；
- 关系解除；
- 记录更正。

### 5.2 事件内容

每条事件包含事件类型、发生日期、内容、证据说明、负责人、创建人、创建时间、关联对象和可选指标快照。

一条事件可以同时关联一个项目、一个井对和一至多口单井。各详情页只查询与当前对象关联的事件，因此同一治理动作无需重复填写。

项目状态改变、关系确认和关系解除自动生成事件。人工事件由管理员创建。

### 5.3 更正与追溯

已保存事件不直接覆盖或硬删除。填写错误时将原事件标记为“已更正”，填写更正原因并创建一条指向原事件的新记录。时间线同时保留两条记录并突出当前有效记录。

## 6. 数据模型

### 6.1 `channeling_well_profiles`

- `id`：主键；
- `well_no`：用于展示的井号；
- `normalized_well_no`：唯一索引；
- `block`：区块，可由数据推断或由管理员补充；
- `owner`：负责人；
- `created_at`、`updated_at`。

井角色不持久化，按关系与现有数据动态计算，避免角色变化后档案失真。

### 6.2 `channeling_tracking_events`

- `id`：主键；
- `event_type`：事件类型；
- `occurred_on`：业务发生日期；
- `content`：事件内容；
- `evidence`：证据或附件说明；
- `owner`：负责人；
- `metrics_snapshot_json`：效果评价快照，无快照时为 `NULL`；
- `supersedes_event_id`：更正时指向原事件；
- `voided_at`、`void_reason`：原事件被更正时填写；
- `created_by`、`created_at`。

### 6.3 `channeling_tracking_event_links`

- `event_id`；
- `subject_type`：`project`、`relation` 或 `well`；
- `subject_id`：对应对象主键；
- `(event_id, subject_type, subject_id)` 唯一约束。

服务层在事务内验证所有关联对象存在。删除对象前检查事件链接，避免产生孤立时间线。

## 7. 接口设计

### 7.1 单井档案

- `GET /api/channeling-wells`：按井号、区块和角色筛选档案。
- `POST /api/channeling-wells`：管理员新建独立档案；规范化井号重复时返回已有档案。
- `GET /api/channeling-wells/:id`：单井基本信息、角色和关联摘要。
- `PATCH /api/channeling-wells/:id`：管理员维护区块和负责人。
- `GET /api/channeling-wells/:id/metrics?start=&end=`：读取角色自适应指标与曲线。
- `GET /api/channeling-wells/:id/relations`：列出该井参与的项目和井对。

### 7.2 项目与井对指标

- `GET /api/channeling-projects/:id/summary?start=&end=`：项目自动汇总。
- `GET /api/channeling-relations/:id/detail?start=&end=`：关系信息和联动曲线。
- `POST /api/channeling-relations/:id/evaluations`：创建效果评价事件和指标快照。

### 7.3 跟踪事件

- `GET /api/channeling-tracking-events?subjectType=&subjectId=`：按对象读取时间线。
- `POST /api/channeling-tracking-events`：管理员新增可关联事件。
- `POST /api/channeling-tracking-events/:id/corrections`：管理员创建更正事件并作废原事件。

所有写接口使用现有管理员鉴权。读接口沿用现有游客只读规则。日期、事件类型、内容、负责人和关联对象在服务器端校验。

## 8. 删除与历史保护

- **解除关系：** 将关系状态改为 `released`，自动写入解除事件，保留关系和所有历史。
- **删除关系：** 仅当关系没有任何跟踪事件时允许硬删除；否则返回 `409` 并提示使用“解除关系”。单井档案不随关系删除。
- **删除项目：** 仅当项目没有关系且没有时间线时允许删除；否则返回 `409`，要求先解除或迁移关系。单井档案不随项目删除。
- **单井档案：** 本期不提供硬删除入口，防止破坏跨项目历史；错误井号通过档案更正流程处理。

## 9. 界面状态与错误处理

- 每个自动指标模块独立显示加载、成功、空数据和失败状态。
- 某个自动模块失败时，基本档案和人工时间线仍可查看。
- 保存失败时保留表单内容并显示服务器返回的明确错误。
- 请求携带当前 `updated_at`；服务器发现版本落后时返回 `409`，提示刷新后重试，避免多人修改静默覆盖。
- 日期范围非法、结束早于开始或缺少对比分界日期时不发起计算。
- 自动数据展示最后查询时间；评价快照展示快照生成时间。

## 10. 权限

- **管理员：** 新建和维护单井档案，关联项目与井对，新增事件，提交评价，确认或解除关系，创建更正记录。
- **游客：** 只读查看项目、井对、单井、自动指标和全部时间线。
- `production` 与 `injection_stage_rows` 在本模块始终只读。

## 11. 测试与验收

### 11.1 单元测试

- 井号规范化与唯一档案匹配。
- 井角色自动判断。
- 项目关联井去重和汇总计算。
- 缺失数据不补 0，前后有效天数正确。
- 效果评价快照结构与重新计算行为。
- 事件更正、链接验证和删除保护。

### 11.2 接口测试

- 管理员写入成功、游客写入返回 `403`。
- 不存在对象、非法日期和非法事件类型返回 `400/404`。
- 重复建档返回已有档案，不创建重复行。
- 有时间线的关系和项目硬删除返回 `409`。
- 自动指标失败不影响时间线接口。
- 乐观并发冲突返回 `409`。

### 11.3 界面测试

- 关系行存在“查看详情/跟踪记录”。
- 项目、井对、单井之间可以双向跳转。
- 未加入项目的单井可以独立建档。
- 注入井、采油井和双角色井显示正确模块。
- 空数据、加载失败和最后查询时间正确显示。
- 多次事件按发生日期和创建时间稳定排序。
- 解除后历史仍可查看，有历史时不显示可执行的硬删除操作。
- 管理员与游客界面权限正确。

### 11.4 完成标准

以下条件全部满足才视为完成：

1. 未加入项目的单井能够独立建档并查看已有自动数据。
2. 每条注窜关系均可进入井对详情和两个单井档案。
3. 项目指标只汇总关联井且不重复计算同一单井。
4. 三个层级均能保存并查看完整治理时间线。
5. 效果评价保存自动指标快照与人工结论，重新计算不改写历史。
6. 解除、删除和更正行为符合历史保护规则。
7. 缺失数据不显示为 0，不产生自动注窜结论。
8. 自动化测试覆盖核心计算、接口权限、删除保护和关键界面流程。
