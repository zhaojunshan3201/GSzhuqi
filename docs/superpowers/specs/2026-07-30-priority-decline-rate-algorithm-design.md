# 重点情况上月递减率算法统一设计

## 目标

“重点情况分析与建议”页面的“上月递减率”必须直接复用“区块生产动态生成器”的递减率算法和区块归并口径，不再维护独立公式或独立区块标准化逻辑。

页面仍固定展示分析截止日期之前一个自然月的各区块递减率。

## 统一口径

### 时间范围

- 目标月份：分析截止日期 `asOfDate` 的上一个自然月。
- 基准年份：目标月份所在年份的上一自然年。
- 上年产量：基准年份 1 月 1 日至 12 月 31 日的区块累计产油量。
- 当前产量：目标月份内有效日报数据形成的区块月平均日产油。
- 闰年折算：使用目标月份所在年份的实际天数，即 365 天或 366 天。

### 公式

```text
递减率 =（上年全年累计产油量 − 上月平均日产油 × 当年天数）
        ÷ 上年全年累计产油量 × 100%
```

计算必须调用 `src/lib/blockProductionGenerator.ts` 导出的共享算法，不在重点情况模块内复制公式。

### 数据完整性

只有同时满足以下条件时才生成递减率：

1. 上一自然年 12 个月均存在有效生产数据；
2. 上一年累计产油量大于 0；
3. 目标月份存在有效日产油数据。

数据不足时返回 `declineRate: null`，并保留明确原因：

- 上年月份不完整：`上年1—12月数据不足`
- 目标月无数据：`目标月无有效产量`

### 区块归并

重点情况页面必须使用 `src/lib/blockProductionGrouping.ts` 中的 `normalizeProductionBlockGroup`，与区块生产动态生成器保持一致。

不得再使用注汽预测模块的 `normalizeForecastBlock` 处理该图表数据。

## 数据流

1. `/api/priority-situation` 读取生产日报和分析截止日期。
2. 服务端把原始区块名称通过 `normalizeProductionBlockGroup` 归并。
3. 按区块、日期汇总日产油，与区块图表接口的日汇总口径一致。
4. 累计上一自然年的全年产量，并检查月份完整性。
5. 计算目标月份的平均日产油。
6. 把目标月份和月平均日产油传给共享递减率算法。
7. API 返回区块、月份、上年累计量、上月平均日产油、递减率及可用状态。
8. 前端沿用现有横向柱状图，正递减为红色，负递减为绿色，显示一位小数和百分号。

## 代码边界

### `src/lib/blockProductionGenerator.ts`

- 保留递减率公式的唯一实现。
- 如有必要，增加一个面向单个数据点的共享函数，再由现有 `calculateDeclineRateSeries` 和重点情况服务共同调用。
- 不改变区块生产动态生成器当前展示行为。

### `server.ts`

- `buildPriorityBlockDeclines` 改用生产动态区块归并函数。
- 按日汇总后计算月平均，避免同一天多井记录与图表接口口径不同。
- 调用共享递减率算法。

### `src/lib/prioritySituationAnalysis.ts`

- 删除不再使用的独立递减率公式，避免形成第二套实现。
- 其它五类重点情况算法保持不变。

### `src/components/PrioritySituationAnalysis.tsx`

- 保持现有图表结构、排序、颜色和空状态。
- 副标题调整为能够表达共享口径的文案，例如“区块生产动态生成器递减率口径”。

## 测试

采用测试驱动方式完成：

1. 新增失败测试，证明重点情况服务直接使用共享算法与生产动态区块归并。
2. 验证普通年和闰年的年化天数。
3. 验证同一区块多种原始名称按生产动态生成器规则合并。
4. 验证上一年度不足 12 个月时不计算。
5. 验证目标月缺少有效日产油时不计算。
6. 验证重点情况 API 返回值与共享算法对相同输入的结果一致。
7. 运行区块生产动态生成器测试、重点情况相关测试和生产构建。

## 非目标

- 不调整其它五类重点情况算法。
- 不改变区块生产动态生成器的日期选择、图表样式或交互。
- 不改变递减率风险分级和异常清单排序。
- 不补造缺失月份或缺失产量。

## 验收标准

- 两个页面只有一个递减率公式实现。
- 两个页面使用同一套区块归并规则。
- 同一批生产数据、同一目标月份下，两处递减率结果一致。
- 上一年数据不完整时不显示虚构递减率。
- 相关自动化测试与生产构建通过。
