# 注采驾驶舱统计图增强设计

## 目标

基于注采驾驶舱现有生产、注汽跟踪、选井与评价数据，在不新增数据源、不修改 Excel 模板和数据库结构的前提下，增加运行状态、生产效果和异常待办三类统计图，使管理人员可以在一屏内完成全局判断并下钻处理问题。

## 页面结构

采用“一屏均衡型”布局。保留现有数据健康卡和核心指标卡，在其下增加四个统计区域：

1. **运行状态分布（环形图）**
   - 展示生产、正注、焖井、待转抽、数据待补全的井数和占比。
2. **各区块注采状态（堆叠柱状图）**
   - 按区块对比各生命周期状态的井数。
3. **各区块生产效果（柱线组合图）**
   - 柱形展示日产油和累计增油，折线展示油汽比。
   - 不同量纲使用独立坐标轴，并明确标注单位。
4. **异常待办分布（横向条形图）**
   - 展示数据缺失、未评价、低效井、焖井逾期、待转抽逾期数量。
   - 默认按数量从高到低排列。

桌面端采用左 1、中 1.5、右 1 的视觉权重组织首屏；中等宽度变为两列，窄屏变为单列。视觉继续使用现有白底、浅灰边框和蓝绿色主色，不引入大屏深色主题。

## 数据口径

不新增数据源。所有统计来自现有驾驶舱聚合所使用的数据。

- 同一口井只使用最新一条注汽跟踪记录，避免重复统计。
- 状态口径沿用现有生命周期映射：生产、正注、焖井、待转抽、数据待补全。
- 区块日产油和累计增油由该区块有效井记录汇总。
- 区块油汽比按有效周期产油量合计除以有效实际注汽量合计计算。
- 缺失数值保持缺失，不以 `0` 代替；对应井计入“数据待补全”或相关异常。
- 图表汇总数字必须能与顶部指标卡和待办列表相互核对。

## 接口设计

扩展现有只读驾驶舱响应，增加：

```ts
type CockpitChartData = {
  blockStatusSummary: Array<{
    block: string;
    producing: number;
    injecting: number;
    soaking: number;
    pendingTransfer: number;
    needsData: number;
  }>;
  blockPerformanceSummary: Array<{
    block: string;
    dailyOil: number | null;
    cumulativeOilGain: number | null;
    oilSteamRatio: number | null;
  }>;
  alertDistribution: Array<{
    type: 'needsData' | 'notEvaluated' | 'lowEfficiency' | 'soakingOverdue' | 'transferOverdue';
    count: number;
  }>;
};
```

接口保持只读。局部数据不可用时，仅将对应字段返回为 `null` 或空数组，不影响其他可用统计。

## 前端设计

- 在现有 `InjectionProductionCockpit` 页面增加图表区域。
- 使用项目已有的 ECharts 和 React 图表封装，不增加新的图表依赖。
- 将图表数据转换和 ECharts 配置拆分为独立纯函数，页面组件只负责请求、状态和交互。
- 图例支持隐藏和显示系列；悬停提示展示区块、数值、占比和单位。
- 每张图独立处理空数据，显示“数据待补全”，不阻断整页。

## 下钻交互

- 点击区块状态或生产效果图形，进入注汽跟踪页面并带入区块筛选。
- 点击异常条形，进入注汽跟踪页面并带入异常类型筛选。
- 环形图用于总览，不额外增加新的详情页面。
- 下钻沿用现有页面导航方式，不修改浏览器路由结构。

## 错误处理

- 聚合接口整体失败时沿用当前驾驶舱错误提示和重试入口。
- 单类统计缺少有效数据时，该图显示局部空状态，其他图继续显示。
- 图表不得把缺失数据渲染成零值柱、零值折线或虚假占比。
- 未知状态统一归入“数据待补全”，不创建新的隐式状态。

## 测试与验收

### 自动化测试

- 后端测试覆盖最新记录去重、区块状态汇总、区块效果汇总、异常分类和缺失值处理。
- 前端纯函数测试覆盖系列顺序、单位、空数据和排序。
- 运行现有测试套件、TypeScript 检查和生产构建，确认没有新增回归。

### 浏览器验收

1. 页面同时显示四张统计图，桌面首屏信息完整。
2. 运行状态、生产效果、异常待办三类信息均可见。
3. 图表数字与顶部指标卡和待办列表一致。
4. 缺失数据明确显示“数据待补全”，不伪装成零。
5. 图例、悬停提示和点击下钻可正常使用。
6. 中等宽度为两列，窄屏为单列，无横向溢出。

## 范围外事项

- 不增加新的 Oracle、实时施工或锅炉数据接入。
- 不新增历史趋势预测、模型分析或经济优化。
- 不修改 Excel 导入模板、导入流程和数据库表结构。
- 不重构与驾驶舱统计图无关的页面。
