# 注汽项目流程闭环二期设计

## 目标

在现有 SQLite 与人工/Excel 录入边界内，为每口注汽井建立“方案计划—正注—焖井—转抽生产—效果评价—关闭”的项目流程。二期不接入实时施工、锅炉数据或 Oracle 自动同步。

## 新增能力

### 注汽方案计划

- 每条方案包含：方案编号、井号、区块、注汽工艺、计划注汽量、计划压力、计划排量、计划正注日、计划焖井日、计划转抽日、负责人、备注和方案状态。
- 方案状态为：草拟、已下达、已取消、已关闭。
- 从“注汽选井”进入时可预填井号与区块；不改变既有选井评分规则。
- 方案仅在“已下达”后允许进入正注流程。

### 流程执行

项目执行状态独立于方案状态：待实施、正注、焖井、待转抽、转抽生产、已关闭。

允许的状态流转：

```text
待实施 → 正注 → 焖井 → 待转抽 → 转抽生产 → 已关闭
```

- 每次状态流转记录实际发生时间和操作备注。
- 不允许跳过前置状态，不允许从已关闭重新流转。
- 实际转抽确认后，将关联的注汽跟踪记录更新/创建为生产状态；无法匹配既有记录时，保留待关联提示，不能静默创建不完整生产数据。

### 焖井与转抽管理

- 待办按计划焖井日、计划转抽日和实际状态生成。
- 焖井状态超过计划转抽日为“转抽逾期”；待转抽状态超过计划转抽日为“待转抽逾期”。
- 页面显示焖井天数、计划转抽日、实际转抽日和逾期天数。

### 既有模块联动

- 注汽跟踪展示关联方案编号、项目状态和计划/实际日期偏差。
- 驾驶舱待办优先链接到项目流程记录；没有关联项目时保留原注汽跟踪下钻。
- 效果评价仅聚合项目状态为“转抽生产”或“已关闭”的记录；保留原始历史记录的查询能力。

## 数据模型

新增：

- `injection_projects`：方案和当前项目状态。
- `injection_project_transitions`：不可变状态流转日志。

`injection_projects` 至少包括：`id`、`project_no`、`well_no`、`block`、`process_type`、`planned_steam`、`planned_pressure`、`planned_rate`、`planned_injection_date`、`planned_soaking_date`、`planned_transfer_date`、`actual_injection_date`、`actual_soaking_date`、`actual_transfer_date`、`plan_status`、`lifecycle_status`、`owner`、`remark`、`created_at`、`updated_at`。

## 权限与错误处理

- 访客只读；沿用当前编辑权限模型进行新增、编辑和状态流转。
- API 对无效状态流转返回 409，缺少必填字段返回 400，不存在记录返回 404。
- 所有日期由用户输入；无计划转抽日时不生成逾期告警。

## 验收标准

1. 可创建、编辑、下达和取消注汽方案。
2. 可按既定顺序完成状态流转，并记录每次操作。
3. 无法跳过状态或重新打开已关闭项目。
4. 焖井/转抽待办能正确标示逾期。
5. 驾驶舱、注汽跟踪和效果评价可读取项目关联状态。
6. 既有注汽跟踪和评价数据不被迁移或删除。
7. 方案创建、流转、逾期计算和接口错误均有自动化测试。
